# 百业战复盘 · 分析框架

> **用途**：定义「怎么分析」。所有复盘必须遵循本框架，以保证不同场次报告结构一致、结论可比较。
> **配套**：规则依据见 `rules.md`，报告结构见 `report-structure.md`。

---

## 0. 三条不可违背的原则

1. **证据优先**：任何结论必须能落到「时间戳 + 帧编号 + 可观察事实」。无法观察到的内容一律标注为「不可判定」，禁止编造。
2. **区分事实与推断**：事实陈述用肯定句；推断必须加限定词（「推测」「可能」「证据表明」），并在报告中单列「推断依据」与「置信度」。
3. **责任分离**：团队问题不等于个人问题。同一个现象（如「团战脱节」）可能源于指挥未发指令、也可能源于个人无视野跟进，必须分别归因，不得笼统归罪。

## 1. 输入解析与视角模式

复盘前必须先判定录像类型，不同视角决定了「个人决策与操作」维度是否可分析。

| 模式 | 特征 | 可分析维度 |
| --- | --- | --- |
| `pov`（第一人称/玩家本人视角） | 单一玩家镜头，含其技能释放、走位、语音提示 | 三维度全开，个人维度可做到操作级 |
| `spectator`（观战/上帝视角） | 自由镜头或导播视角 | 队伍维度最强；个人维度只能分析**镜头跟随到的对象** |
| `mixed`（混合，含小地图+主观视角） | 常用组合 | 三维度全开，可交叉验证 |
| `highlight`（集锦/剪辑） | 已剪辑，时间不连续 | **禁止**做阶段节奏分析；只能做片段级操作分析 |

**强制要求**：若录像为 `highlight` 或镜头频繁切换且无法定位「我」，必须在报告开头声明**分析范围限制**，不得输出「全场节奏」类结论。

## 2. 时间轴锚点规范（决定「上下半场」怎么切）

### 2.1 优先级（从高到低）

1. **游戏内对局计时器**：若画面 HUD 存在剩余时间/已用时间倒计时，逐帧读取并建立映射表（帧编号 ↔ 游戏内时间）。这是**唯一权威**时间基准。
2. **游戏内事件锚点**：中场表演提示、张豹/朱骨击杀播报、人墙摧毁播报、鹅被击杀播报、树被搬运提示。
3. **视觉转场**：明显黑屏、结算画面、准备阶段 UI。
4. **兜底**：以上均无法识别时，按视频总时长**等分**（上半场 0–50%，下半场 50–100%），并在报告中**明确标注为「估算分界」**。

### 2.2 上下半场的两种切法

- **切法 A（默认，时间轴切分）**：以对局计时中点切分。33 分钟对局 → 上半场 0:00–16:30，下半场 16:30–33:00。
- **切法 B（事件切分）**：以「中场表演」或「第一座人墙被摧毁」为分界。适用于用户明确以「中场」为界的要求。

**默认采用切法 A**；若用户/录像存在明确中场事件且与中点偏差 > 2 分钟，采用切法 B，并在报告中说明理由。

### 2.3 锚点表产出物

抽帧后必须生成 `timeline.json`，字段如下（供报告引用与用户校正）：

```json
{
  "source": "match.mp4",
  "video_duration_sec": 2070.0,
  "clock_detected": true,
  "clock_map": [{"frame": "frame_000120.jpg", "t_video": 300.0, "t_match": "05:00"}],
  "anchors": [
    {"type": "half_break", "t_video": 990.0, "t_match": "16:30", "evidence": "HUD 倒计时重置"},
    {"type": "halftime_show", "t_video": 1020.0, "t_match": "17:00", "evidence": "中场表演 UI"}
  ],
  "halves": {"first": [0.0, 990.0], "second": [990.0, 2070.0]}
}
```

## 3. 分层抽帧策略（「逐帧分析」的工程实现）

**现实约束**：33 分钟 30fps 视频约 59,400 帧，逐帧送入视觉模型不可行且无必要。采用**分层抽样 + 事件回溯**，在关键区间逼近逐帧精度。

| 层级 | 目的 | 采样粒度 | 触发条件 |
| --- | --- | --- | --- |
| L1 概览 | 建立全场节奏、阶段划分 | 每 10–15 s 1 帧 | 全程必做 |
| L2 阶段 | 识别团战/推进/僵持段 | 每 3–5 s 1 帧 | 全程必做 |
| L3 事件 | 定位关键动作前后 | 每 0.5–1 s 1 帧，事件前后各 5 s | 检测到事件（见 §2.1-2）时 |
| L4 精确 | 复核具体操作 | 每 0.1–0.2 s 1 帧（≈5–10 fps） | 存在争议/需确认操作细节时 |
| L5 原片回溯 | 无法从静帧判定时 | 直接调取对应时间段原视频片段 | 静帧信息不足（如需要看技能冷却流转） |

**硬性要求**：
- L1/L2 必须覆盖**上下半场**，不得只抽上半场。
- 每一条被写入报告的「操作级结论」必须至少有 **L3 或更高**等级的帧证据。
- 报告必须在附录列出**抽帧参数**（粒度、总帧数、覆盖区间），保证可复现。

## 4. 三维度分析模型

### 维度一：队伍整体问题（宏观 / 指挥层）

检查项（逐项给结论，无证据则写「未观察到」）：

| 编号 | 检查项 | 判定要点 |
| --- | --- | --- |
| T1 | 阶段节奏 | 是否在 0–8 min 完成清野囤币？8–16 min 是否拔出首塔？16 min 后是否围绕朱骨组织团战？ |
| T2 | 目标优先级 | 关键节点是否在打**该打的**目标（例：未破塔却打鹅） |
| T3 | 人墙三路分配 | 是否有分线偷塔？人墙是否被过度前压/无人补位？ |
| T4 | 中场表演处置 | 是否参与？人选是否最强止戈？扣塔/扣鹅选择是否最优？ |
| T5 | 首领争夺 | 张豹/朱骨是否开视野、集结、争夺？失败原因是信息、人数还是执行？ |
| T6 | 战场货币使用 | 指挥是否及时释放技能？是否有囤积？技能与团战节奏是否对齐？ |
| T7 | 团战协同 | 开团与跟进是否同步？有无救援/集火指令？脱节频次与时长？ |
| T8 | 防守与回防 | 敌方搬树/偷塔时，回防响应时间与人数？ |
| T9 | 陷阱/诡圣使用 | 陷阱布置位置是否有效？关键回合是否使用？ |
| T10 | 终局判定意识 | 终局 3 分钟是否按「判定链条」优化（破塔数 / 人墙血量 / 树距离）？ |

### 维度二：个人决策问题（中观）

针对**分析对象**（若 `pov` 模式即玩家本人；若 `spectator` 模式需先明确分析对象名单）逐条检查：

| 编号 | 检查项 | 判定要点 |
| --- | --- | --- |
| P1 | 目标选择 | 每次切换目标是否服务于团队当期目标？有没有「打无关野怪/追残血」的偏离？ |
| P2 | 站位 | 是否站在己方阵型内？是否站在技能范围与治疗范围内？有无孤军深入？ |
| P3 | 时机 | 进攻/撤退时机是否与团队同步？是否有「早开/晚退」？ |
| P4 | 风险收益 | 高风险动作（单人抢首领、越塔）收益是否匹配？死亡是否划算？ |
| P5 | 资源取舍 | 刷野 vs 参团、守塔 vs 偷塔 的取舍是否合理？ |
| P6 | 信息行为 | 是否先获取视野再行动？是否利用小地图判断敌方位置？ |
| P7 | 团队贡献 | 关键动作（打断搬树、护送、集火）中是否有该对象的参与？ |
| P8 | 死亡质量 | 每次死亡：是否可避免？是否有价值（换到目标）？ |

### 维度三：操作问题（微观）

| 编号 | 检查项 | 判定要点 |
| --- | --- | --- |
| O1 | 技能衔接 | 连招顺序是否正确、是否有技能空窗被打断 |
| O2 | 关键技能命中 | 控制/爆发是否命中？空放比例？ |
| O3 | 走位微操 | 是否有无效走位、卡地形、面向错误 |
| O4 | 反应速度 | 面对突袭/控制的反应是否滞后（以帧间隔估算） |
| O5 | 资源管理 | 药品/耐力/技能 CD 是否在需要时可用 |
| O6 | 视角控制 | 镜头是否丢失目标、是否未观察威胁来源 |
| O7 | 交互精度 | 拾取/搬运/占领等交互是否中断或失败 |

> **操作维度的诚实边界**：静帧无法判定「按了什么键」。所有 O 类结论只能是**现象级**（「该次攻击未命中」），不得断言「操作手法错误」除非有连续帧证据。

## 5. 失误定级标准

| 级别 | 名称 | 判定标准 | 对局影响 |
| --- | --- | --- | --- |
| **S** | 致命 | 直接导致失败条件成立（丢树、丢鹅、满盘崩） | 直接决定胜负 |
| **A** | 重大 | 造成显著资源/节奏/人数差（单人送首领、指挥弃用货币、误用规则） | 明显改变走势 |
| **B** | 中等 | 局部效率损失（脱节、漏视野、站位失误被集火） | 累积影响 |
| **C** | 轻微 | 细节瑕疵，无实质影响（走位重叠、无效跑位） | 可忽略但可优化 |

**定级要求**：每条失误必须写出定级理由（「因为…」），且理由需引用 §4 检查项编号或 `rules.md` 小节号。

## 6. 评分量表（用于横向对比不同场次）

对每个维度给出 0–10 分，并**必须**给出扣分依据：

| 分数段 | 含义 |
| --- | --- |
| 9–10 | 该维度几乎无失误，执行接近教材级 |
| 7–8.9 | 个别 B 级失误，整体达标 |
| 5–6.9 | 存在 A 级失误或大量 B 级失误，需针对性训练 |
| 3–4.9 | 存在 S 级失误或系统性缺陷 |
| 0–2.9 | 该维度基本失效（如指挥全程未使用技能） |

**总分**：三维度加权（队伍 40% / 个人决策 35% / 操作 25%）。权重可在报告中按用户要求调整，但须显式声明。

## 7. 结论书写规范（每条问题的固定结构）

```
【时间】上半场 06:32（视频 00:06:32，frame_000391.jpg）
【事实】全队 5 人在敌方 2 号人墙处集火，未开启战场货币技能，敌方 3 人绕后打野张豹。
【规则依据】rules.md §6 张豹为中期核心经济资源；§5.2 指挥应在关键团战前释放增益。
【问题定级】A 级 —— 目标优先级错位 + 指挥未使用货币技能。
【影响】张豹被敌方击杀，中期经济差约 1 个技能周期，直接导致 09:40 团战失利。
【改进建议】设立「首领刷新提醒」；指挥建立「团战前 15 秒必放增益」硬性规则。
```

**禁止**：只写「这里打得很乱」这类无锚点、无依据的评价。

## 8. 常见反模式（分析者自身的错误，必须避免）

1. **结果倒推**：因为输了就判定所有决策错。必须区分「决策错」与「决策对但执行失败」。
2. **上帝视角指责**：用全局信息指责玩家未获知的信息。判定个人失误时必须考虑**该玩家当时可获得的信息**。
3. **无锚点结论**：不给时间戳和帧号的评价。
4. **混淆维度**：把操作问题写成决策问题（或反之）。
5. **编造细节**：画面看不清却描述出具体技能名/血量数值。
6. **忽略规则**：不了解规则就评价（例：不知道打鹅需先破塔）。
7. **只批评不给方案**：每条问题必须配可执行建议。
