# 百业战复盘报告 · 结构与写作规范

> **用途**：定义 PDF 交付物的固定章节、每章必填内容、Markdown 语法约定。
> **配套**：分析内容规范见 `analysis-framework.md`；规则依据见 `rules.md`。
> **产出方式**：本文件定义的 Markdown → `scripts/build_report.py` → HTML → PDF。

---

## 1. 章节骨架（必须按此顺序，章节可增不可减）

```
# 封面（自动生成，见 §3）

## 0. 报告信息与声明
## 1. 对局概览
## 2. 关键时间轴
## 3. 总体结论与评分
## 4. 上半场分析
### 4.1 上半场 · 队伍整体问题
### 4.2 上半场 · 个人决策问题
### 4.3 上半场 · 操作问题
### 4.4 上半场 · 阶段小结
## 5. 下半场分析
### 5.1 下半场 · 队伍整体问题
### 5.2 下半场 · 个人决策问题
### 5.3 下半场 · 操作问题
### 5.4 下半场 · 阶段小结
## 6. 上下半场对比
## 7. 改进建议清单（按优先级）
## 8. 附录
```

## 2. 各章节必填内容

### 0. 报告信息与声明
- 录像文件名、时长、分辨率、帧率
- **视角模式**（`pov` / `spectator` / `mixed` / `highlight`）及由此产生的**分析范围限制**
- 分析对象（`pov` 模式下为玩家本人；`spectator` 模式下须列出被分析者）
- 抽帧参数（层级粒度、总帧数、覆盖区间）
- **不确定性声明**：哪些结论为推断、哪些字段不可判定

### 1. 对局概览
以表格给出可观察的客观事实：

| 字段 | 值 | 来源 |
| --- | --- | --- |
| 最终胜负 | 胜/负/未知 | 结算画面 |
| 终局判定依据 | 直接搬运成功 / 树推进距离 / 破塔数 / 人墙血量 | 见 `rules.md` §2 |
| 己方破塔数 / 被破塔数 | n / m | HUD 或播报 |
| 鹅状态（双方） | 存活 / 被击杀 | HUD |
| 树状态 | 未出现 / 己方搬运中 / 敌方搬运中 / 搬运成功 | HUD |
| 中场表演结果 | 我方胜/负/未参与 | 播报 |
| 张豹归属 | 我方/敌方/未击杀 | 播报 |
| 朱骨归属 | 我方/敌方/未击杀 | 播报 |

> 无法从画面确认的字段填「不可判定」，**禁止猜测具体数值**。

### 2. 关键时间轴
表格形式：`视频时间 | 对局时间 | 事件 | 帧编号 | 影响评级`。
至少覆盖：准备结束、首次破塔、中场表演、张豹、朱骨、鹅被击杀、树被搬运（如有）、终局。

### 3. 总体结论与评分

- **一句话结论**（≤ 40 字，直指最核心问题）
- **评分表**：

| 维度 | 得分 | 主要扣分点 |
| --- | --- | --- |
| 队伍整体 | /10 | |
| 个人决策 | /10 | |
| 操作 | /10 | |
| **加权总分** | **/10** | 权重 40/35/25 |

- **Top 3 关键失误**（S/A 级），每条一行。

### 4–5. 上下半场分析
每个半场必须包含**三个维度小节**，每小节内按时间顺序排列问题条目。条目格式严格遵循 `analysis-framework.md` §7 的固定结构（时间/事实/规则依据/定级/影响/建议）。

小节末尾给该半场**该维度评分 + 一句话评价**。

### 6. 上下半场对比
必须包含：
- 对比表（维度 × 半场得分）
- **趋势判断**：进步 / 恶化 / 持平，并给出证据
- **半场差异根因**：如体力/心态/对手调整/指挥换人

### 7. 改进建议清单（按优先级）
表格：`优先级 | 适用层级（队伍/个人/操作）| 具体动作 | 可验证标准 | 关联问题编号`

- 优先级 P0（必须立即改）/ P1（本周内）/ P2（长期训练）
- **可验证标准**必须可量化，例：「每次团战前 15 秒必释放一次增益技能，全场 ≥ 5 次」

### 8. 附录
- 抽帧参数与帧清单（或帧文件夹路径）
- 关键帧图片（每章至多 4 张，带图注「图 N：视频 mm:ss —— 说明」）
- 术语表（鹅 / 树 / 人墙 / 战场货币 / 诡圣 / 止戈）
- 版本与规则来源说明

## 3. 封面生成规则

`build_report.py` 依据以下前置标记读取封面信息：

```
<!-- COVER
title: 燕云十六声 · 百业战对局复盘报告
subtitle: 录像：match_20261016.mp4 ｜ 视角：pov
meta: 上半场 0:00–16:30 ｜ 下半场 16:30–33:00
date: 2026-10-16
-->
```

封面后自动插入目录（由 `build_report.py` 依据标题生成）。

## 4. Markdown 书写约定

| 元素 | 约定 |
| --- | --- |
| 图片 | `![图注](../frames/frame_000391.jpg)`，路径相对报告 md 文件 |
| 失误定级 | 用行内标记 `**A 级**`，便于脚本高亮 |
| 时间锚点 | 统一写作 `上半场 06:32` 或 `下半场 21:05` |
| 表格 | 标准 GFM 表格语法 |
| 引用块 | 用于「规则依据」摘录 |
| 提示框 | `> **P0**：……` 用于高优先级建议 |

**强调色约定**（由 CSS 实现，无需手写颜色）：
- 含 `S 级` / `A 级` 的段落 → 红色左边框
- 含 `B 级` → 橙色左边框
- 含 `C 级` → 灰色左边框
- 含 `P0` → 深红标签

## 5. 写作质量红线

1. 不使用「发挥不好」「打得很乱」等**无信息量**评价。
2. 不出现**无时间戳**的问题条目。
3. 不与 `analysis-framework.md` §8 的七条反模式冲突。
4. 每条问题必须配**可执行、可验证**的建议。
5. 报告长度建议控制在 **8–20 页**；若素材不足，宁可缩短也不注水。
